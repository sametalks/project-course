GitHub Projects Portfolio Observatory
My interpretation of the brief
The project aims to build an analytical, Trello-style portfolio observatory on top of GitHub Projects. While GitHub Projects manages individual workflows well, tracking delivery risks, stale items, and priority shifts across multiple repositories and projects is difficult. The application connects to multiple project boards via GitHub's GraphQL API, normalises heterogeneous field configurations into a unified data model, records historical snapshots, and visualises role-specific dashboards.

Why I am a good fit for this project
I am focused on modern web architectures, API integration, and clean data modeling. Building a cross-project monitoring layer requires a balance between backend data ingestion and responsive UI design. I value building modular, maintainable tools that solve real project-management visibility challenges without introducing excessive operational complexity.

Relevant experience and background
I have practical experience developing web and desktop applications, working with TypeScript, component-based architectures, and relational or lightweight document databases. I am familiar with Git, API consumption, token-based authentication workflows, and managing state across asynchronous processes.

Proposed approach
I will first investigate the GitHub Projects v2 GraphQL API to define rate limits, query pagination, and the normalized schema for custom fields (status, priority, deadline, assignee). I will implement a lightweight backend (such as PocketBase) to store project field mappings and time-stamped status snapshots. On the frontend, I will build a responsive dashboard using SvelteKit and TypeScript, featuring dedicated personal, team, and high-level wallboard views with stale-item and overdue alerts.

Initial plan
Research GitHub Projects GraphQL API schema, permissions, and rate-limiting behaviors.

Define the core domain model for normalized work items, field mappings, and historical snapshots.

Set up the local persistence layer and mock project synchronization pipelines.

Implement API authentication, project field mapping configuration, and data ingestion.

Develop the SvelteKit frontend dashboard with filtering, stale item detection, and activity feeds.

Write unit and integration tests for field normalization, snapshotting, and monitoring rules.

Additional information
The project will be version-controlled in Git from day one with structured commit messages. All access tokens and sensitive environment variables will remain strictly outside the repository.
